# Update Nx Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the repository from Nx 19.5.6 to the latest stable Nx release and apply the migration while keeping the `github.io` app verified.

**Architecture:** Use Nx's official migration workflow as the source of truth for package updates and codemods. Follow with narrow peer dependency alignment for Vite, Vitest, TypeScript, ESLint, `@typescript-eslint/*`, and React Vite plugin packages only when migration output or verification requires it.

**Tech Stack:** Nx, pnpm, React, Vite, Vitest, ESLint, TypeScript, `@nx/*` plugins.

## Global Constraints

- Upgrade all installed Nx packages to the latest stable release available at implementation time.
- Run the official Nx migration flow and apply generated migrations.
- Allow migration-driven formatting, config reshaping, and file organization changes when they are part of keeping the workspace current.
- Align closely coupled packages only when needed for latest Nx compatibility: Vite, Vitest, TypeScript, ESLint, `@typescript-eslint/*`, and React Vite plugin packages.
- Preserve the `github.io` app's user-facing behavior unless a migration requires a small mechanical compatibility adjustment.
- Keep unrelated packages unchanged unless they block installation or verification.
- Do not redesign the `github.io` app.
- Do not add deployment, CI, or GitHub Pages workflows.
- Do not perform a full dependency refresh beyond Nx and coupled toolchain packages.
- Do not upgrade Astryx, commit tooling, Husky, or unrelated libraries unless required by peer dependencies or verification failures.
- Stage explicit paths only. Do not use `git add -A`, `git add --all`, `git add -u`, `git add .`, `git commit -a`, or `git commit -am`.

---

## File Structure

Expected changed files:

- `package.json`: Nx and coupled toolchain dependency versions.
- `pnpm-lock.yaml`: pnpm lockfile after migration and install.
- `migrations.json`: temporary/generated Nx migration plan if Nx creates it; keep it only if the final migration flow requires it to remain.
- `nx.json`: workspace-level inferred target/plugin configuration updated by Nx migrations.
- `tsconfig.base.json`: TypeScript compiler or project reference changes if generated by migration.
- `apps/github.io/project.json`: app target metadata if Nx migration materializes or reshapes project config.
- `apps/github.io/vite.config.ts`: Vite/Vitest config compatibility edits if generated or required.
- Other lint, TypeScript, or test config files touched by official Nx migrations.

Do not create new source modules or redesign app components for this work.

### Task 1: Generate And Apply Official Nx Migration

**Files:**
- Modify: `package.json`
- Modify: `pnpm-lock.yaml`
- Modify: `migrations.json` if generated
- Modify: `nx.json` if generated by Nx
- Modify: any workspace config files touched by the Nx migration command

**Interfaces:**
- Consumes: Existing Nx 19.5.6 workspace in `package.json` and `nx.json`.
- Produces: A dependency and migration state where all installed Nx packages target the latest stable release.

- [ ] **Step 1: Confirm clean branch state**

Run:

```bash
git status --short --branch
```

Expected: branch is `chore/update-nx-tools` and the working tree is clean before migration changes.

- [ ] **Step 2: Ask Nx to generate latest stable migrations**

Run:

```bash
corepack pnpm nx migrate latest
```

Expected: Nx updates `package.json`, may update `pnpm-lock.yaml`, and may create `migrations.json`. If the command needs network access and the sandbox blocks it, rerun the same command with escalation and record the original failure.

- [ ] **Step 3: Install migrated dependencies**

Run:

```bash
corepack pnpm install
```

Expected: pnpm completes successfully and updates `pnpm-lock.yaml`. If peer dependency warnings appear, record them for Task 2 rather than making broad manual package changes here.

- [ ] **Step 4: Run generated migrations**

Run:

```bash
corepack pnpm nx migrate --run-migrations
```

Expected: Nx applies every generated migration. If `migrations.json` does not exist because Nx had no migrations to run, record that and continue.

- [ ] **Step 5: Inspect migration results**

Run:

```bash
git status --short
git diff -- package.json nx.json tsconfig.base.json apps/github.io/project.json apps/github.io/vite.config.ts migrations.json
```

Expected: the diff is limited to Nx migration output and coupled workspace config. If unrelated dependencies changed, identify whether Nx changed them or whether they should be reverted before commit.

- [ ] **Step 6: Verify installed Nx package versions are aligned**

Run:

```bash
node -e "const p=require('./package.json'); const deps={...p.dependencies,...p.devDependencies}; for (const [k,v] of Object.entries(deps).filter(([k])=>k==='nx'||k.startsWith('@nx/')).sort()) console.log(k+' '+v);"
```

Expected: `nx` and all installed `@nx/*` packages point to the same latest stable major, unless Nx's own migration explicitly uses a different compatible version for a package.

- [ ] **Step 7: Commit official migration output**

Run:

```bash
git add package.json pnpm-lock.yaml nx.json tsconfig.base.json apps/github.io/project.json apps/github.io/vite.config.ts migrations.json
git diff --cached
git commit -m "chore(nx): migrate tooling to latest stable"
```

Expected: commit succeeds. If one of the listed files does not exist or is unchanged, omit that explicit path and rerun `git add` with only existing changed paths.

### Task 2: Resolve Coupled Toolchain Compatibility

**Files:**
- Modify: `package.json`
- Modify: `pnpm-lock.yaml`
- Modify: `nx.json` if plugin options require adjustment
- Modify: `apps/github.io/vite.config.ts` if Vite or Vitest config requires adjustment
- Modify: lint or TypeScript config files only if verification output points to them

**Interfaces:**
- Consumes: Latest stable Nx migration output from Task 1.
- Produces: Compatible versions and config for Vite, Vitest, TypeScript, ESLint, `@typescript-eslint/*`, and React Vite plugin packages.

- [ ] **Step 1: Run peer dependency check**

Run:

```bash
corepack pnpm peers check
```

Expected: PASS. If it fails, note each failing peer relationship and continue to Step 2.

- [ ] **Step 2: Identify only coupled package updates required by failures**

Run:

```bash
corepack pnpm why vite vitest typescript eslint @typescript-eslint/parser @typescript-eslint/eslint-plugin @vitejs/plugin-react
```

Expected: output shows which direct packages participate in the failing peer graph. Do not update Astryx, Husky, commit tooling, or unrelated packages unless this output or Nx migration output requires it.

- [ ] **Step 3: Apply the smallest compatible coupled package updates**

If Step 1 failed, update only the direct dependencies implicated in the peer failures. Prefer pnpm's workspace-root dev dependency command:

```bash
corepack pnpm add -Dw vite@latest vitest@latest typescript@latest eslint@latest @typescript-eslint/parser@latest @typescript-eslint/eslint-plugin@latest @vitejs/plugin-react@latest
```

If fewer packages are implicated, remove the unrelated package names from the command before running it.

Expected: `package.json` and `pnpm-lock.yaml` update only the coupled packages required for compatibility.

- [ ] **Step 4: Re-run install and peer check**

Run:

```bash
corepack pnpm install
corepack pnpm peers check
```

Expected: both commands pass.

- [ ] **Step 5: Inspect and commit compatibility fixes**

Run:

```bash
git diff -- package.json pnpm-lock.yaml nx.json apps/github.io/vite.config.ts
git add package.json pnpm-lock.yaml nx.json apps/github.io/vite.config.ts
git diff --cached
git commit -m "fix(nx): align migrated toolchain peers"
```

Expected: commit succeeds if compatibility fixes were needed. If Task 2 made no changes because peer checks already passed, skip this commit and record that no follow-up peer alignment was needed.

- [ ] **Step 3: Test the app**



- [ ] **Step 5: Re-run the failed command and then the full verification set**

Run:

```bash

corepack pnpm peers check
NX_DAEMON=false corepack pnpm nx build github.io
NX_DAEMON=false corepack pnpm nx lint github.io
NX_DAEMON=false corepack pnpm nx test github.io
```

Expected: every command passes.

- [ ] **Step 6: Commit verification fixes if any were needed**

Run:

```bash

git add apps/github.io/project.json apps/github.io/vite.config.ts nx.json package.json pnpm-lock.yaml
git diff --cached
git commit -m "fix(github.io): restore migrated nx targets"
```

Expected: commit succeeds if verification fixes were needed. If Task 3 made no changes, skip this commit and record that verification passed without target/config fixes.
