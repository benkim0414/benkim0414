# GitHub.io Storybook Design

Date: 2026-07-13

## Summary

Add Storybook to the existing `github.io` Nx React app so components and the app shell can be viewed visually from an iPad while developing over Blink.sh and mosh.

The first Storybook setup is app-local. It supports component iteration for the current abstract Astryx app shell and does not introduce a shared UI library or Storybook deployment.

## Goals

- Configure Storybook for `apps/github.io`.
- Use Nx Storybook support for the React/Vite application.
- Make the Storybook dev server reachable from the iPad with a fixed host and port.
- Split the current app shell into small, storyable React components.
- Add focused stories for the app shell parts plus one full-shell integration story.
- Preserve the current visual intent of the basic abstract app shell.

## Non-Goals

- Do not create a shared UI/component library yet.
- Do not deploy Storybook.
- Do not add real portfolio, resume, project, or contact content.
- Do not redesign the app shell beyond the small structure needed for storyable components.
- Do not add browser automation or visual regression testing in this first Storybook setup.

## Repository Context

The repository is an Nx monorepo using pnpm. The `github.io` app already exists at `apps/github.io` as a Vite React application. The workspace is on Nx `23.0.2` with React, Vite, Vitest, ESLint, and Astryx dependencies already present.

The app currently uses Vite configuration in `apps/github.io/vite.config.ts`. The `apps/github.io/project.json` file keeps explicit project metadata while Nx infers targets from configuration.

## Architecture

Add Storybook only to `apps/github.io`. Use Nx's Storybook generator and executors so Storybook participates in the workspace graph and exposes normal Nx targets such as `storybook` and `build-storybook`.

Keep Storybook configuration project-local under:

```text
apps/github.io/.storybook/
```

The configuration should use Storybook's React/Vite framework path that matches the Nx generator output. The Storybook preview should import the same global app styles needed for Astryx and layout rendering, so stories match the app instead of rendering as unstyled React fragments.

Storybook should be configured for the user's iPad workflow:

- Host: `0.0.0.0`
- Port: `4400`

This makes the server reachable from the iPad through the user's existing remote/dev-machine network path while keeping the command predictable.

## Component Boundaries

Split the current app shell into focused components only where it improves Storybook usefulness:

- `AppShell`: composes the full page shell.
- `TopBar`: renders the sticky top bar and navigation labels.
- `HeroIntro`: renders the main intro heading and supporting placeholder copy.
- `PlaceholderSection`: renders repeated placeholder content areas.
- `SiteFooter`: renders the quiet footer.

The app entry should continue to render the same full app experience. Static placeholder data can stay close to the app shell unless a small local module improves readability.

Each component should have a clear prop surface only when needed. Avoid premature abstraction for content that is still purely placeholder.

## Stories

Add component-focused stories for the app shell pieces:

- `TopBar`
- `HeroIntro`
- `PlaceholderSection`
- `SiteFooter`
- `AppShell`

Include one full-shell story for integration review. Component stories should use representative placeholder labels and copy, not real personal content.

Stories should use Storybook's current Component Story Format conventions generated by the Nx setup. Keep story files near the app components unless the generator establishes a different project-local convention.

## Data And State

Storybook stories use static props and static placeholder data only. There are no API calls, routing state, persistence, or mocked network layers in this design.

## Error Handling

There is no data-loading error surface in this setup.

Configuration errors should fail visibly during Storybook startup or build. Do not hide missing Astryx styles, broken imports, or Storybook/Vite integration problems behind fallback rendering.

## Testing And Verification

Verification should include:

- Install/update dependencies with pnpm as needed.
- Run `pnpm nx build-storybook github.io`.
- Run `pnpm nx build github.io`.
- Run `pnpm nx lint github.io`.
- Run `pnpm nx test github.io`.

For interactive verification, run Storybook with the `github.io` Nx target and confirm it starts on `0.0.0.0:4400`. If the environment cannot prove iPad reachability directly, record the local listening URL and the command used.

## Implementation Constraints

- Work in a linked git worktree.
- Use pnpm for package and Nx commands.
- Prefer Nx generators for Storybook configuration.
- Keep changes scoped to `github.io`, Storybook dependencies/configuration, and required workspace metadata.
- Stage explicit paths only.
- Use conventional commits.
