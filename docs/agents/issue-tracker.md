# Issue tracker mapping for mattpocock/skills

This repository uses Hermes Kanban as the local agent task tracker for the v1 multi-profile workflow unless a task explicitly names GitHub Issues, a PR, or another tracker.

Related setup docs: `docs/agents/triage-labels.md`, `docs/agents/domain.md`.

## Tracker

- Primary agent tracker: Hermes Kanban (Cursor Project / Kanban board; not GitHub Issues by default)
- Repository: `benkim0414/benkim0414`
- Project-specific instructions: root `AGENTS.md`
- When a skill says "publish to the issue tracker": create or update a Hermes Kanban ticket (or the tracker the task explicitly names)
- When a skill says "fetch the relevant ticket": read the Kanban/issue reference the user or prior skill provided

## Role/state vocabulary

mattpocock/skills triage vocabulary should map to Hermes Kanban states as follows:

| mattpocock role/state | Hermes/Kanban meaning |
| --- | --- |
| `bug` | Bug/fix task category |
| `enhancement` | Feature/improvement task category |
| `needs-triage` | Backlog/Scheduled; needs `triage` inspection |
| `needs-info` | Blocked; waiting for user/reporter clarification |
| `ready-for-agent` | Ready; can be assigned to `implement` or `code-review` |
| `ready-for-human` | Awaiting handoff/user approval; do not auto-push/deploy |
| `wontfix` | Cancelled/closed with reason |

## Profile routing

- `triage`: clarify, research, write spec, create tickets.
- `implement`: implement ready implementation tickets; no push/deploy.
- `code-review`: review implementation against spec and standards; no push/deploy.
- `handoff`: manual final gate; only profile allowed to push/open PR/deploy after explicit user approval.

## Ticket requirements

Each ticket should include:

- Problem/goal
- Target app/package/project
- Branch/worktree expectations
- Acceptance criteria
- Blocking edges / dependencies
- Validation commands to try
- Handoff criteria

Prefer vertical tracer-bullet slices. Wide refactors should use expand-contract sequencing.

## Posting comments

If posting to GitHub Issues or PRs, start generated comments with:

> *This was generated by AI during triage.*

For local Hermes Kanban comments, include a concise role prefix such as `triage:`, `implement:`, `code-review:`, or `handoff:`.

## Manual handoff gate

Do not automatically push, merge, or deploy when review passes. Move the work to an awaiting-handoff state and wait for the user to explicitly invoke `handoff`.
